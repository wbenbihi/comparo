# Comparo 0.4.0 — preparation notes

**Status:** implemented on the preparation branch, not yet tagged or published.
**Baseline:** `v0.3.0` (`0f2bcf5`, 2026-11-02). The release also includes the subsequent
`feat(cli): add starter project initialization` commit. GitHub Actions derives 0.4.0 from feature
commits after review and merge; package metadata and the lock stay at 0.3.0 until that version commit.

## Resource exploration

Explorer explains a resource without asking the user to assemble an execution plan.

- **Value:** press `r` to resolve public nested fields, linked Values and available Project/
  Environment inputs directly. No consumer is required, including in a project with no Requests
  or Environments. Secrets and secret-derived values are masked; one unavailable input or masked
  sibling does not conceal the rest of the document.
- **Matrix:** inspect axes and explicit/include/exclude declarations, browse generated cases and
  read the selected case's values. Case pages replace execution-plan, consumer, binding, trial and
  previous/next-match controls. Source/Graph visits preserve the selected case and page.
- **Request:** Summary gathers the HTTP target and attachments. Body shows numbered, indented JSON
  with keyboard selection and a synchronized path/value/directive/declaration inspector. Copy
  contains only the already masked preview; body inspection sends no Request.
- **Schema:** browse actual object nesting, array item schemas, nested required flags, definitions
  and combinators. Project-local references expand across schema resources; recursive branches
  stop explicitly. The definition pane retains the source schema and JSON Pointer, and reference
  rows open their declaration.
- **Relationships:** typed resource links and Back preserve the previous resource, view, filter,
  cursor, focus and scroll position. Stale worker output is rejected after selection/context changes.
- **Other resource kinds:** Environment values/groups, execution settings, rule/profile details,
  Scenario steps and policy/capture groups use the shared inspector components.
- **Actions and colors:** resource actions use the compact shared ActionBar. Masked data uses a
  dedicated violet token; JSON booleans are blue, warnings amber and failures red. `<masked>` and
  redaction labels remain visible when color is unavailable. Both built-in themes are supported.

The [Explorer contract](../explorer-0.4.0-plan.md) and [TUI guide](../tui.md) document controls and
limits. Backend implementation details are in the [resource component guide](../codebase/tui-resource-components.md)
and [application API reference](../codebase/application-api-reference.md).

## Starter projects

`comparo init [DIRECTORY]` creates one starter `comparo.yaml` containing two local Environments,
a health Request and assertion/diff/gate profiles. Existing manifests are never overwritten.
Resources start in the manifest; no `.comparo/` directory is created. Edit the URLs and health
endpoint before execution. See [CLI initialization](../cli.md#start-a-project).

## Try the branch

From a checkout with the development environment installed:

```console
.venv/bin/comparo tui --config examples/explorer-inspection/comparo.yaml
```

This [inspection fixture](../../examples/explorer-inspection/README.md) needs no server and includes
secret canaries, nested JSON, cross-schema references and cycles. A bare `comparo` can still select
an older pipx installation. Quit and restart the TUI after Python changes; project reload does not
reload its modules. Settings → General shows the package version and build information. Seeing
0.3.0 in an editable checkout before release is expected and does not identify which source code
was loaded; use the explicit workspace executable.

## Compatibility and limits

There is no configuration or artifact schema version change: `comparo/v1alpha1` and the existing
artifact/report contracts remain in use. No project migration is required for these inspectors.
A Value inspected independently uses Project/active-Environment inputs; an execution-specific
parameter or Matrix input that exists only in a consumer is unavailable in that standalone view.
The existing execution path retains its normal prepared-plan semantics.

Preview bounds remain explicit: Matrix expansion 10,000 cases, 50 cases/page, 64 value nodes;
Body document 512 lines and resolved batches of 16 field targets; Schema tree 512 nodes/depth 32.
Truncated previews are not complete payload exports. Remote Schema acquisition/cache and sample
validation are not Explorer controls. Scenario execution, generic resource editing, broader
accessibility preferences and cursor/retention/annotation Reports controls remain deferred.
