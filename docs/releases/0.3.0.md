# Comparo 0.3.0 — proposed release notes

**Status:** proposed minor release, pending PR review and GitHub Actions qualification.
Scope: all changes from `v0.2.0` to the `refactor` branch. These notes describe the final supported
implementation rather than intermediate TUI prototypes that were added and subsequently removed.

The existing pre-1.0 semantic-release configuration (`allow_zero_version = true`,
`major_on_zero = false`) produces **0.3.0** for this history. A no-operation preview confirmed that
version. CI creates the version commit/tag after merge; this document does not announce publication.

## Core architecture and configuration

- Replace the prototype's internals with immutable typed domain contracts and frontend-neutral
  application services. Separate configuration, planning, value resolution, execution, evaluation,
  HTTP, persistence and presentation; enforce these boundaries with import and architecture checks.
- Introduce the `comparo/v1alpha1` compiler with bounded source discovery, source-located parsing,
  namespace/kind-aware references, composition and overrides, dependency linking, diagnostics,
  provenance and deterministic fingerprints.
- Compile Projects, Environments, Requests, Matrices, Values, Schemas and execution/validation/
  safety/redaction/artifact profiles. Scenario declarations remain inspectable but non-executable.
- Provide authored, effective and masked resolved inspection, revision-pinned source/outline
  references, field-composition explanations and bounded batches for frontend use.

## Planning, values and execution

- Add deterministic admitted plans for assertions across Environments and directed baseline-to-
  candidate comparisons, with reusable ExecutionProfiles, Matrix case expansion, repeated trials,
  retries, fail-fast and resource budgets.
- Support typed invocation overrides for selections, values, Requests, profiles and limits. Share
  precedence and admission between CLI and TUI rather than interpreting them in widgets.
- Introduce one-shot prepare/review/start checkpoints, exact occurrence coordinates, safe request
  previews and lazy windows for large plans. Changed controls require a new review.
- Resolve values at explicit run/cell/trial/environment/execution/attempt scopes, with isolated
  Environment inputs, caching, sealed sensitive values and cancellation-aware cleanup.
- Expose asynchronous execution sessions, cancellation, bounded live occurrence/rule facts,
  timings and recent events. Terminal completion, evaluation outcomes and gate verdicts remain
  distinct; final artifacts supply the authoritative results.

## HTTP and evaluation

- Replace the previous high-level HTTP path with a route-authorized `httpcore` transport, explicit
  TLS/proxy handling, ordered request fields, typed body/auth materialization and connection reuse.
- Reauthorize redirects, bound retry delays and total deadlines, decode ordinary/gzip responses,
  and handle bounded SSE streams, including structured JSON event data.
- Share the selector engine between typed assertions and semantic diffs. Add assertion operations
  for equality, ordering, tolerance, membership, strings, keys/cardinality, regex, media, digests,
  decoding and schemas.
- Support semantic diff transforms, reducers and singular/ordered/keyed/set/multiset pairing,
  with stable normalized facts and gate reduction across multiple rules.
- Validate local response JSON Schemas as ordinary gated assertions. Fetch remote public root
  schemas only under explicit authority and limits; transitive remote fetching remains unsupported.

## Artifacts, reports and security

- Define independently versioned `comparo.artifact/v1alpha1` artifacts and
  `comparo.report/v1alpha1` JSON report envelopes. Compile sanitized output before persistence.
- Persist private POSIX bundles atomically; authenticate manifests and detached captures, verify
  lineage/counts and bind body/cURL references to exact artifact revisions and HTTP exchanges.
- Retain sanitized request/response metadata, attempt/exchange timings, redaction/omission counts,
  run annotations and provenance. Missing or unavailable evidence remains explicit.
- Add bounded result collections, Issues/Requests/Rules/Fields/Timeline projections, raw body
  windows, JSON subtree/SSE event paging and sanitized stored-request cURL export.
- Export JSON, Markdown, JUnit XML and SARIF. Backend archive APIs support cursor queries and
  reviewed retention/trash/restore; those advanced operations are not yet Reports controls.
- Separate operator-owned ExecutionPolicy from project restrictions. Enforce destination-bound
  secret egress, single-use exchange authorization, scoped values and exception/diagnostic
  containment; harden cancellation ownership and sensitive-evidence sanitization.

## CLI

- Rebuild the command adapter with Cyclopts/Rich over the shared application services.
- Provide schema generation, validation, planning, security diagnostics, sanitized rendering,
  Request assertions, directed diffs, execution profiles, artifact inspection/verification/blob
  reads, report export and shell completion.
- Expose caller-owned sources, inputs, policy, execution and capture limits with structured failures.
- Launch the canonical TUI through `comparo tui`, `python -m comparo.tui`, or bare `comparo` in an
  interactive terminal. Redirected bare invocation remains headless help.

## Terminal interface

- Promote the component-based interface developed as TUI4 to `comparo.tui`; remove the old
  terminal implementations and versioned entry points. Reuse the shared component library,
  semantic method colors, entity glyphs, status grammar and responsive layouts.
- **Explore:** resource hierarchy and kind-specific inspectors; authored/effective/resolved views,
  Request tabs, dependency navigation, explicit Environment/Matrix context, Environment health
  checks and selected Request/profile handoff to Launch.
- **Launch:** intent-first Target selection for Requests, profiles or assertions; section-based
  keyboard navigation, readable scope/variants, exact Plan review and explicit execution approval.
  Save representable manual targets as new ExecutionProfiles after reviewing YAML and destination.
- **Run:** evolving request/case status, adjacent environment lanes, HTTP codes, durations,
  assertion/diff counters, progress and activity. Preserve selection and the completed summary
  until the user explicitly opens Analyze.
- **Analyze:** shared issue/request/rule/field/timeline navigation, occurrence context, rule
  evidence, HTTP attempts/exchanges and body comparisons. Use macOS-compatible Alt+1–5 or bracket
  navigation; expose meaningful empty/omitted-evidence states.
- **Capture inspector:** shared raw paging, JSON subtrees, SSE events and reviewed sanitized cURL
  copying. Preserve exact request/environment/attempt identity and restore Analyze selection.
- **Reports:** searchable/date-grouped bounded archive, filters, outcome/provenance/integrity
  preview, the same Analyze component and explicit non-overwriting exports.
- **Settings:** General first with package identity, license/source and build SHA; separate
  Appearance, Interaction and Keyboard sections, plus a read-only Plugins placeholder. Persist
  theme, spacing, startup workspace, mouse and supported shortcut remaps; retain drafts between
  sections. Show the actual Environment/version in the application header.
- **Debug:** keep the reusable component gallery available for development and review.

## Packaging, quality and documentation

- Embed source revision and modified-source state in wheels/sdists; preserve provenance when
  building a wheel from an sdist. Rebuild release assets after the version commit and verify
  their installed SHA before publication.
- Restrict distribution members to reviewed package/build files and exclude quarantined prototype,
  local state and sensitive files. Verify archive integrity and smoke-test installed wheels.
- Keep Python 3.13+ support with CI compatibility jobs for 3.13 and 3.14. Update the transport,
  CLI, YAML, selector/regex and terminal dependency stack and lock the development environment.
- Expand unit, integration, property, security, architecture, CLI and Textual Pilot coverage,
  including loopback HTTP and terminal layouts at 80, 120 and 160 columns.
- Provide three runnable example projects and a local demo server, including Matrix, streaming,
  assertion-only and mixed Launch review profiles.
- Refresh configuration/report guides, workspace and application contracts, architecture, security,
  code-health inventory, contribution guidance and design QA. Preserve obsolete audits and
  prototype documentation as explicitly historical references.

## Upgrade notes and remaining scope

This is a **0.3.0 minor release in the pre-1.0 line**, with compatibility changes that must be
reviewed before upgrading:

- Prototype `comparo/v1` configuration and resource `$ref` syntax are not accepted as aliases by
  the new compiler. Use the current `comparo/v1alpha1` authoring guide and examples.
- Retired TUI entry points and the old input/output/navigation-limit flags are removed. Use
  `comparo tui --help` for the current CLI surface.
- Artifact/report contracts are independently versioned; prototype saved-result compatibility is
  not promised. Linux/macOS support the current POSIX local value/artifact adapters; Windows
  execution/persistence support is not claimed.
- Fields shows retained rule evidence, not every captured JSON property. Body inspection requires
  successfully retained persisted captures. Reports currently uses a bounded listing rather than
  the backend's large-archive cursor API.
- Stateful Scenarios, WebSocket/gRPC, community plugins/LLM judges, arbitrary resource editing,
  broader accessibility preferences and a dedicated distributable Comparo CI action remain deferred.
  Browser automation remains outside the product scope.

## Release qualification

Publication is pending. The second GitHub Actions run passed Python 3.13 and 3.14 compatibility,
but the main check failed a profile-save timing test and the then-configured 100% coverage gate
(measured **98.00%**). The shared action bar now preserves controls and keyboard focus when
availability changes; regressions also cover profile-save errors and safe publication.

The maintainer approved a **95% overall statement-and-branch coverage floor** on November 2.
Branch measurement and existing tests remain enabled. This is an explicit quality-policy change,
not a claim that the uncovered paths have been tested. Targeted checks and package verification
are recorded in [current status](../status.md); only a passing full GitHub Actions run qualifies
the release, including compatibility and installed-wheel verification.

Resolve CI findings, review this migration and merge only after qualification. The
[release guide](../releasing.md) describes validation, versioning, publication and recovery.
